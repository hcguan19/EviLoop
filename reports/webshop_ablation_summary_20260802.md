## 初步结论

1. 单候选恢复取得当前最高成功率（34.0%）和结账精度（94.4%），说明当前多候选恢复流程可能引入循环、DOM 状态阻塞或错误候选切换。
2. 去除购买门禁后结账次数上升到 20，但只有 2 次完全成功，说明门禁能够抑制错误提交，但当前门禁或恢复联动也可能过度阻止提交。
3. 仅通用 Agent 有 23 次结账，但只有 4 次满足全部约束，主要问题是商品属性和选项验证不足。
4. 去除 Memory 后平均 Token 大幅下降，但 50 条均未完成提交；该组同时存在上下文超限问题，不能仅据此认定 Memory 的净贡献。

## 有效性说明

本轮完整方法、去除 Memory、去除语义重排等组受到 DOM/Screenshot Watchdog 超时、16K 上下文超限和早期 API 中断影响。尤其 Full 组包含 26 条超时。因此本表适合作为故障诊断和下一轮实验设计依据，不应直接作为论文最终消融表。正式论文版本需要修复基础设施问题后，用相同 50 条任务和 seed=17 重跑受污染组。
